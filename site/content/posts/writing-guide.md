文章放在 `content/posts/` 下，一个 `.md` 文件就是一篇。**文件名（不含扩展名）就是
文章的 slug**，也就是它的网址。

## front matter

文件开头用 `---` 包起来的部分是元信息：

```yaml
---
title: 文章标题
date: 2026-09-19
author: Felix
summary: 列表页上显示的一句话摘要
tags:
  - 建站
  - Rust
draft: false
---
```

除 `title` 外都可以省略。`draft: true` 的文章不会出现在任何列表里，直接用网址也
访问不到，所以发布前忘了改也不至于漏出去。

`author` 写的是**发布者的站点账号用户名**。不写就默认 `Felix`——单人站点里内容都归
站长，没必要每篇都抄一遍。将来有别人发布，各自在自己的文件里写自己的用户名；页面上
会链到那个人的主页，站内没有同名账号时只显示名字、不给链接。

## 生效方式

内容在**进程启动时**载入内存，因此改完文件要重启服务才能看到：

```bash
cargo leptos serve
```

## 正文里能写什么

标题、列表、引用、表格、代码块、脚注都可以。引用块长这样：

> 写下来才算想过。

表格：

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 否 | 省略时用文件名代替 |
| `date` | 否 | 用于排序，格式 `YYYY-MM-DD` |
| `author` | 否 | 发布者的站点账号用户名，省略时用 `Felix` |
| `summary` | 否 | 列表页摘要 |
| `tags` | 否 | 数组，用于标签页 |
| `draft` | 否 | 默认 `false` |

正文里的裸 HTML 是被放行的（文章由站长自己写）；但**评论与评价里的 HTML 会被过滤
掉**，因为那些内容来自访客。
